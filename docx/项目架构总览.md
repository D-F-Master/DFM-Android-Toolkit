# DFM-Android-Toolkit 项目架构总览（AI 阅读版）

> 用途：给 AI（或新人）快速建立对本仓库的完整认知。所有路径均为相对仓库根 `D:\uTools\`。
> 生成方式：基于对各子目录源码的实际研读（2026-11-14），非 README 抄写；README 已滞后于代码，以本文为准。

## 1. 项目一句话定位

uTools 插件 + Electron 桌面壳 + FastAPI 本地服务端 + Android 探针 APK 的一体化 Android 调试工具箱：通过 ADB 实现设备管理、应用管理、文件管理、批量投屏、日志调试、串口透传、jar 对比/改码、SQLite 查看、MCP 服务管理，另附端口/IP 工具与生产流水线功能。

## 3. 组件详解

### 3.1 DFM-service — FastAPI 本地服务端（核心后端）

- **入口**：`DFM-service/main.py`。`create_app()` 在 `DFM-service/config/app_config.py`（CORS 全开、lifespan 挂内存任务队列），挂载 14 个 router 后由 uvicorn 监听 `DFM-service/conf/conf.json` 的 HOST/PORT（`0.0.0.0:3000`），版本 2.0.3。
- **两种模式**：`--mode server`（阻塞跑服务）/ `desktop`（pywebview 窗口加载 `http://127.0.0.1:3000`）。启动时 `DFM-service/config/tool_check.py` 的 `check_tool_availability()` 校验 adb/scrcpy/aapt/data/conf。
- **路由清单**（前缀均在 `/api`，测试路由在 `/test`）：
  - `routes/adb_utils.py`：设备/应用/文件/按键/日志/音量/监控/证书等 ~40 端点（/devices、/command、/device/app/*、/device/files/*、/device/scrcpy、/device/monitor 等）。
  - `routes/port_utils.py`：端口检查/杀进程/扫描/telnet、Windows portproxy 管理。
  - `routes/ip_utils.py`：IP 扫描、在线检测、批量 adb connect。
  - `routes/remote_ws.py`：`/ws/remote` WebSocket 批量投屏（JSON 控制帧 + 二进制 H.264：1B 设备号 + 1B 帧类型）。
  - `routes/script.py`：模拟脚本 CRUD/导入导出 zip/回放。
  - `routes/serial.py`：模拟串口（adb 推设备端工具 serial-writer/pty-inject 做 UART 回环与按键注入）。
  - `routes/pipeline.py`：生产流水线（APK 素材库、快照、run-script、游标增量日志）。
  - `routes/probe.py`：DFMProbe 探针对接（check/connect/message）。
  - `routes/jar_diff.py`（`/api/jardiff`）、`routes/jar_edit.py`（`/api/jaredit`）：jar 对比（CFR 反编译）与在线改码（javac 重编译替换）。
  - `routes/sqlite_utils.py`：拉取设备 SQLite 并增删改查推送。
  - `routes/mcp_utils.py`：MCP server 模板生成/安装（独立 venv）/启停/心跳，每个 server 占 3010~3050 端口。
  - `routes/common.py`（`/cp/decode` 主机截屏转 base64）、`routes/test_routes.py`（队列演示）。
- **响应/错误/鉴权**：手写 `{code, message, data}`（200/500）信封，无统一异常处理器、无鉴权、CORS `*`。
- **lib/**：内置 adb/scrcpy/aapt 工具包（缺失时回退系统 PATH），另含 `lib/cfr.jar` 供 jar 反编译。
- **关键 utils**：
  - `utils/tool_manager.py`：统一工具路径解析（内置优先，支持 PyInstaller `_internal` 布局），全局使用。
  - `utils/app_label_utils.py`：aapt 提取 APK 应用名，缓存到 `data/app_labels.json`。
  - `utils/jar_diff_core.py`：zip 对比 + CFR/javap；`utils/md_export.py`：差异导出 markdown。
- **静态托管**：前端构建产物放 `DFM-service/data/dist`，由 `config/html_config.py` 的 `/{full_path:path}` SPA 兜底路由服务（⚠️ 该路由必须最后注册，`main.py:42` 有注释）。
- **scrcpy 两条路径**：`/device/scrcpy` 直接 Popen 弹窗；`routes/batch_remote.py` 按 scrcpy v3.3.3 协议自实现 DeviceSession（push server + adb forward + 视频/控制双 TCP）。
- **打包**：`main.spec`（onedir，产物 `ylx-utools-server`，datas 含 data/conf/lib）与 `main-onefile.spec`；`run.bat` 指向 dist 下 exe。

### 3.2 DFM-frontend — uTools 插件前端（主前端）

- **技术栈**：Vue 3 + Vite（dev 端口 5175，`host: true` 解决 Node 24 下 ::1 白屏），集成 CodeMirror 6、ECharts、Element Plus 风格消息。
- **插件入口**：`DFM-frontend/public/plugin.json` 只注册一个功能入口 `code: "DFM-Android-Toolkit"`，main 指向 `index.html`；preload 为 `public/preload/services.js`（CommonJS），向渲染进程注入 `window.services`（readFile / writeTextFile / writeImageFile，写 `utools.getPath('downloads')`）。
- **无 vue-router / pinia**：`src/App.vue` 用 `MENU_ITEMS` 注册表 + `currentPage` ref 切页。
- **页面与接口**（API 基址来自 `public/config.json` 的 `apiBase`，默认 `http://localhost:3000`）：
  - `src/menu/App_Utils.vue`（ADB 工具，约 5100 行 / 350KB，8 个 tab：info/apps/files/keys/batch/script/serial/monitor）→ `/api/device/*` 与 `/api/probe/message`。
  - `src/menu/App_PortTool.vue`（端口工具）→ `/api/port/*`、`/api/portproxy/*`、`/api/ip/*`。
  - `src/menu/App_Production.vue`（生产工具）→ `/api/devices`、`/api/device/pipeline/*`。
  - `src/menu/App_JarDiff.vue`（jar 包工具）→ `/api/jardiff/*`、`/api/jaredit/*`。
  - `src/menu/App_McpService.vue`（MCP 管理）→ `/api/mcp/*`（list/start/stop/uninstall/logs/create-template/upload）。
  - `src/menu/App_Settings.vue`：纯前端，localStorage 持久化，不调后端（与 config.json 是两套配置来源，⚠️）。
- **通用组件**：`src/components/ModalDialog.vue`、`FileEditorDialog.vue`（CodeMirror 编辑器）、`FileImageViewer.vue`、`SqliteDbViewer.vue`；全局配置单例 `src/composables/useAppConfig.js`（fetch `/config.json`，`isFeatureOn('a.b')` 嵌套开关，未配置默认开启）。
- **通信约定**：无统一封装层——axios 与原生 fetch 混用；后端返回 `{success, message, data}` 或 `{code, message, data}`（两种都在用），失败 `ElMessage.error`。
- **构建关键点**：`npm run build` = `vite build && node scripts/patch-utools-dist.mjs`——后者把 dist 的 ESM `<script type="module">` 改为经典 defer 脚本（uTools 以 file:// 加载禁止 ESM）。`vite.config.js` 用 dedupe+optimizeDeps 解决 CodeMirror 6 多副本。

### 3.3 DFM-desktop — Electron 桌面壳

- **入口** `DFM-desktop/main.js`：单实例锁（防多开抢 3000 端口）→ `setupUpdater`（启动查一次更新）→ `startBackend` 拉起后端（打包模式跑 `resources/backend/ylx-utools-server.exe`；开发模式优先 `../DFM-service/dist` 的 exe，回退 venv python 跑 `main.py --mode server`）→ 轮询 `http://127.0.0.1:3000/` 等就绪（60s）→ 1050×700 无菜单窗口 `loadURL(BASE_URL)`（即后端托管页面）。退出时 `taskkill /T /F` 清后端进程树；子进程强制 `PYTHONIOENCODING=utf-8`；日志在 `%TEMP%\dfm-desktop.log`。无托盘、无自启动。
- **frontend/ 与 DFM-frontend 的关系**：独立副本且已分叉（package.json name `dfm-desktop-frontend`；桌面端 `frontend/src/App.vue` 删除了 `App_McpService.vue` 路由）。⚠️ 桌面 README 称"端口工具已移除"，但 `frontend/src/App.vue:22,129` 仍注册渲染 `App_PortTool`，文档与代码不符。
- **update-server/**：零依赖 Node 静态文件服务，默认 8080 端口，只服务 `/updates/*`（latest.yml + Setup exe/blockmap），配合 electron-updater generic provider。⚠️ `package.json` 的 `publish.url` 仍是占位 `http://localhost:8080/updates/`。
- **打包发布**：NSIS x64，`extraResources` 把 `../DFM-service/dist/ylx-utools-server` 打进包；`scripts/afterPack.js` 用 `frontend/dist` 替换包内 `resources/backend/_internal/data/dist`；`scripts/sync-frontend.js` 开发模式同步前端产物到 DFM-service 两处（`data/dist` 与 exe 的 `_internal/data/dist`）。

### 3.4 DFM-probe — Android 无界面探针 APK

- **定位**：无 Activity 的常驻 agent，前台服务 `ProbeService` 监听 `0.0.0.0:21104`，PC 作 TCP 客户端连入做远程验证。adb 只负责安装、广播启动、端口转发，不承载业务数据。
- **激活**：显式广播 `com.dfm.probe.START`（`adb shell am broadcast -n com.dfm.probe/.StartReceiver --include-stopped-packages`）；另有 `BOOT_COMPLETED` 开机自启、60s AlarmManager 看门狗（`java/.../StartReceiver.java:50-62`）、START_STICKY 保活、IMPORTANCE_NONE 隐藏通知渠道。权限仅 3 项：INTERNET、FOREGROUND_SERVICE、RECEIVE_BOOT_COMPLETED。
- **源码极简**：仅 `com.dfm.probe` 两类——`StartReceiver.java`（广播拉起服务）与 `ProbeService.java`（1035 行主体：TCP 监听、每连接单线程、增量解帧/CRC/粘包、命令分发、TTS、设备信息、串口会话 SerialSession/SerialReadTask/SerialSendTask）。
- **能力**：0x00 心跳（回版本）、0x01 TTS 朗读（懒初始化 ≤30s + 朗读等待 ≤60s）、0x02 设备详细信息（安卓版本/SN/内核 + /dev 串口节点、摄像头、外设列表，单项失败降级）、0x04/0x03/0x05/0x07 串口会话（stty 配参 + RandomAccessFile 打开节点，需 root；读缓冲 65536B，PC 轮询取增量；透传不做帧解析，业务帧由 PC 侧解析）。
- **pc/**：`pc/probe_test.py`（469 行）PC 端联调脚本（装 APK、广播、forward/直连、组帧/重传、约 16+ 用例），是参考实现。
- **构建**：`build.ps1` 不用 Gradle——aapt2 → JDK8 javac → JDK17 d8 → zipalign → apksigner（复用工程根 `debug.keystore` 保证可覆盖安装，勿删）。产物 `DFMProbe.apk`（25KB）。SDK/JDK 路径硬编码（`E:\android-sdk-windows`、`D:\jdks\8|17`）。

### 3.5 DFM-ui — 组件库演示页

- 纯浏览器静态站（Vite 6 + Vue 3.5 + TS），从 DFM-frontend 提取的通用组件（`src/components/Button.vue`、`ModalDialog.vue`、`FileEditorDialog.vue`）的演示/预览场，含用法代码片段与设计令牌 `src/styles/tokens.css`（主色 #0d9668）。
- **零后端依赖**：全目录无 fetch/axios/http，数据均为页面内模拟。不参与运行链路，仅作组件孵化。

## 4. 组件交互全景

```
                 ┌───────────────────────────┐
   uTools ──────►│ DFM-frontend (uTools 插件) │──┐
                 └───────────────────────────┘  │
                 ┌───────────────────────────┐  │  REST + WebSocket (/ws/remote)
  浏览器/桌面壳 ►│ DFM-desktop (Electron 壳)  │──┤  http://localhost:3000
   拉起后端进程   │  └ frontend/ (分叉副本)    │  │
                 └───────────────────────────┘  ▼
                              ┌──────────────────────────┐
                              │  DFM-service (FastAPI)    │
                              │  0.0.0.0:3000             │
                              └───────┬──────────┬───────┘
                    subprocess adb/scrcpy/aapt │ adb forward tcp:21104
                                      ▼        ▼
                              Android 设备   DFM-probe APK (TCP :21104,
                              (ADB/串口)     AA55 二进制帧协议)
```

- 前端静态页由 DFM-service 托管（`data/dist`），uTools 插件与桌面壳都以"后端同源页面"方式加载；桌面壳负责拉起/清理后端进程。
- MCP server（`routes/mcp_utils.py` 装的独立 venv 进程）心跳上报 `DFM_MCP_MANAGER_URL`（默认回本服务 3000）。
- DFM-ui 不参与任何调用链。

## 5. Probe 二进制帧协议（摘要）

权威文档：[probe与service通讯协议.md](probe与service通讯协议.md)。帧结构：`AA 55 | 帧序1B | 长度2B(小端) | 命令字1B | UTF-8 JSON 数据区 | CRC16-Modbus(小端)`，数据区单帧 ≤65535 字节。业务帧（0x00~0x05、0x07）要求 ACK（0x06，同帧序、空数据区）；响应帧命令字 = 请求 | 0x80，不要求 ACK；未知命令回 0xFF。停等重传 T=200ms/N=3，响应帧超时 120s，同帧序去重防重复执行（如 TTS 念两遍）。命令字明细见协议文档表格与 [DFM-probe_接口文档.md](DFM-probe_接口文档.md)。

### 与实现不符的两处（协议文档滞后，以代码为准）

1. 帧序去重时机：文档写"业务完成后更新 lastSeq 再回 ACK"，实现是**先更新 lastSeq 并立即回 ACK，再执行业务**（`DFM-probe/java/.../ProbeService.java:276-284`）。
2. 0xFF 适用范围：文档说"未知命令或业务异常"均回 0xFF，实现中**业务异常仍走 `cmd|0x80` 响应帧**，仅未知命令回 0xFF（`ProbeService.java:290`）。

## 7. API 约定

- 服务地址 `http://localhost:3000`，Swagger 在 `/docs`。
- REST 统一 POST 为主，信封 `{code, message, data}`（service 手写约定，部分接口为 `{success, message, data}`，前端两种都处理）。
- WebSocket：`/ws/remote` 批量投屏（JSON 控制帧 + 二进制 H.264：1B 设备号 + 1B 帧类型）。
- Probe：`AA 55` 二进制帧协议（§5），经 `routes/probe.py` 的 HTTP 端点转接给前端。

## 8. 已知风险与注意事项（研读结论）

1. **无鉴权 + CORS `*` + 监听 0.0.0.0**：service 与 probe 的 21104 端口都无鉴权/加密，仅适合可信内网。
2. **双前端副本漂移**：DFM-desktop/frontend 与 DFM-frontend 已分叉（桌面端删了 MCP 页），无同步机制；桌面 README 与代码不符（端口工具仍在）。
3. **大文件**：`App_Utils.vue` 约 350KB/5100 行；`DFM-service/dist.rar` 339MB 在仓库目录内（.gitignore 外，注意勿误提交）。
4. **SPA 兜底路由必须最后注册**（`config/html_config.py` 的 `/{full_path:path}`，`main.py:42` 注释）。
5. **uTools 禁止 ESM**：改动前端构建产物加载方式前先看 `scripts/patch-utools-dist.mjs`。
6. **debug.keystore 勿删**：probe 覆盖安装依赖它。
7. **配置双源**：`App_Settings.vue`（localStorage）与 `public/config.json`（features 开关）并存。
8. **硬编码路径**：`routes/sqlite_utils.py:31` 缓存目录 `D:\log\sqlite_view`；probe 构建的 SDK/JDK 路径。
9. **无统一异常处理/请求封装**：错误信封靠约定，改接口时注意两侧同步。

## 9. 给 AI 的协作约定（摘自 AGENTS.md，长期有效）

- **不要启动、停止或重启任何服务**（含 DFM-service 的 uvicorn/FastAPI、前端 dev server），由用户本人管理。
- 需要验证接口时，先问用户服务是否已在运行，或由用户自行启动后再测。
- 例外：TestClient/独立测试端口的临时验证脚本，验证完立即清理。
- Git 提交流程：每步操作可回溯，commit message 格式 `type(scope): what was done`，多文件修改按逻辑分组提交。
