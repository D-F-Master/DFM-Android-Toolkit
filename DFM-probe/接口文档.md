# 探针接口文档 v2.2

## 基础信息

- **HTTP 服务地址**: `http://localhost:3000`（后端 `DFM-service`，路由 `DFM-service/routes/probe.py`）
- **设备端监听**: TCP `21104`（`DFM-probe/DFMProbe.apk`，`ProbeService`）
- **启动方式**: 后端每次请求发幂等广播 `com.dfm.probe.START`；服务常驻监听 21104，不 force-stop
- **帧协议**: 见根目录 `probe与service通讯协议.md`
- **设备端源码**: `DFM-probe/java/com/dfm/probe/ProbeService.java`（下文简称 `ProbeService.java`）
- **PC 侧源码**: `DFM-service/routes/probe.py`、`DFM-probe/pc/probe_test.py`
- **适用构建**: 保留 `CMD_HEARTBEAT (0x00)`、`CMD_TTS (0x01)`、`CMD_DEVICE_INFO (0x02)`、`CMD_SERIAL_READ (0x03)`、使用 2 字节长度帧协议的 `DFMProbe.apk`

> v2.0 删除了旧业务命令字 `0x01`~`0x05`、`0x07`（PING / ECHO / TTS / INFO / QUIT / DEVICE_INFO），
> 业务命令字重新编号为 `0x00` 心跳、`0x01` TTS；v2.1 新增 `0x02` 设备详细信息（返回设备基础信息、
> 串口 / 摄像头 / 外设列表）；v2.2 新增 `0x03` 串口读取（打开指定串口按波特率读取数据），
> 并补充 `0x03` 真机实测返回、刷卡模块数据帧解析（见 `3.4`）与实机验证记录（见 `五`）。
> 帧层（2 字节长度、ACK、CRC、去重、超时）保持不变，
> 但**命令字不兼容旧版 APK / service / PC 脚本 / 前端**，必须一起升级。

## 统一规范

### 请求方式

HTTP 接口统一使用 **POST**，参数放入请求体（JSON 格式）。

### HTTP 返回格式

与 `DFM-service/API文档_v2.md`「统一规范」保持一致：

**成功响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**失败响应**:

```json
{
  "code": 400,
  "message": "错误信息",
  "data": null
}
```

**状态码说明**:

- `200`: 成功
- `400`: 请求参数错误
- `500`: 服务器内部错误

> `/api/probe/*` 三个端点在通讯失败时仍返回 `code: 200`，`message` 为失败原因（如
> `ACK 等待超时（共发 4 次）`），`data.connected` 为 `false`；仅参数校验失败返回 `code: 400`。

### 帧数据区请求格式

设备端接收的数据区为 UTF-8 JSON **对象**（不能是数组 / `null` / 基本类型），单帧最多 65535 字节。
不是合法 JSON 对象的帧直接丢弃且不回 ACK。各命令字的请求字段见「三、命令字与参数规范」。

### 帧数据区返回格式

设备端应答数据区同样对齐 `DFM-service/API文档_v2.md` 的统一规范，
由 `ProbeService.java:327-343` 的 `ok()` / `fail()` 统一生成，所有命令字（含未知命令与超长兜底）不再使用 `ok` 布尔字段：

**成功**:

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**失败**:

```json
{
  "code": 400,
  "message": "错误信息",
  "data": null
}
```

**字段说明**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | `200` 成功 / `400` 请求参数错误 / `500` 设备端内部错误 |
| `message` | string | 成功固定 `success`；失败为具体错误原因 |
| `data` | object \| null | 成功为该命令字的业务数据对象；失败固定 `null` |

失败时 `data` 固定为 `null`（`JSONObject.NULL`），不省略、不替换成空对象。

### 帧交互流程

业务帧（`0x00`、`0x01`、`0x02`、`0x03`）校验通过先回 ACK（`0x06`），再回同帧序响应帧；
响应帧命令字 = `请求命令字 | 0x80`，不要求 ACK。未知命令字回 `0xFF CMD_ERROR`。
CRC 错或长度非法的帧直接丢弃且不回 ACK；同一帧序重复帧只回 ACK、不重复执行业务。
长度字段为 2 字节、低字节在前，单帧数据区 **最多 65535 字节**。

## 一、HTTP 接口

三个端点统一返回 `{"code":200,"message":"...","data":{...}}`。

| 接口 | 请求体 | 描述 |
| --- | --- | --- |
| `POST /api/probe/check` | `{"deviceId":"..."}` | 只发一帧 `CMD_HEARTBEAT (0x00)` 探测，不安装 APK |
| `POST /api/probe/connect` | `{"deviceId":"..."}` | 先 `adb install -r DFMProbe.apk`，再发一帧 `CMD_HEARTBEAT (0x00)` |
| `POST /api/probe/message` | `{"deviceId":"...","cmd":0,"data":{}}` | 按命令字发一帧，`data` 作数据区，返回设备应答；`cmd` 仅接受 `0` / `1` / `2` |

### 1. 检测探针通讯

**接口**: `POST /api/probe/check`  
**描述**: 不安装 APK，只发一帧 `CMD_HEARTBEAT (0x00)` 确认设备端服务是否在监听并取回程序版本。  
**请求体**:

```json
{"deviceId": "202600298120"}
```

**响应**（结构示意，hex 与端口为示例值）:

```json
{
  "code": 200,
  "message": "通讯正常",
  "data": {
    "connected": true,
    "deviceId": "202600298120",
    "seq": 1,
    "cmd": 0,
    "request": {},
    "response": {"code": 200, "message": "success", "data": {"version": "1.0"}},
    "frame": "AA 55 01 02 00 00 7B 7D ...",
    "frames": {"tx": "AA 55 01 ...", "ack": "AA 55 01 00 00 06 ...", "rx": "AA 55 01 ... 80 ..."},
    "host": "127.0.0.1",
    "port": 41234
  }
}
```

> `request` 由 `DFM-service/routes/probe.py:237` 生成：`data is None` 时填 `{}`。
> USB 设备的 `port` 是系统分配的随机 `adb forward` 本地端口；
> 网络设备（`deviceId` 含 `:`）的 `port` 固定为 `21104`。

### 2. 安装并连接探针

**接口**: `POST /api/probe/connect`  
**描述**: 覆盖安装 APK 后发一帧 `CMD_HEARTBEAT (0x00)`，供页面「安装通讯」使用。  
**请求体**:

```json
{"deviceId": "202600298120"}
```

**响应**: 同「1. 检测探针通讯」，`data` 字段一致。

> `DFMProbe.apk` 路径由 `DFM-service/routes/probe.py:36` 的 `APK_PATH` 解析：
> `DFM-probe/DFMProbe.apk`。源码运行可解析；PyInstaller 打包成 exe 后该路径失效，
> 此端点会返回「找不到 APK」，`/api/probe/check` 与 `/api/probe/message` 不受影响。

### 3. 发送任意命令帧

**接口**: `POST /api/probe/message`  
**描述**: 按指定命令字向设备发一帧，返回设备应答，供页面调试与本文档接口调用。  
**请求体**:

```json
{"deviceId": "202600298120", "cmd": 0, "data": {}}
```

**字段说明**:

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `deviceId` | string | 必填，非空 | ADB 设备序列号；含 `:` 视为网络设备，直连 `<IP>:21104` |
| `cmd` | int | 必填，仅 `0` / `1` / `2` / `3` | 帧命令字，见「二、帧命令字总表」；其余值直接回 `400 cmd 只支持 0x00 / 0x01 / 0x02 / 0x03`，不向设备发帧 |
| `data` | object | 可选，默认 `{}` | 帧数据区，必须是 JSON 对象；序列化后不得超过 65535 字节 |

**响应**: 同「1. 检测探针通讯」；`data.response` 为设备端应答 JSON，
`data.frame` 为发送帧 hex，`data.frames` 为 `tx` / `ack` / `rx` 三段真实帧 hex。

**失败响应**:

```json
{
  "code": 400,
  "message": "deviceId 不能为空",
  "data": {"connected": false}
}
```

> 该端点的参数校验失败沿用既有行为，`data` 为 `{"connected": false}` 而非 `null`；
> 设备端帧应答的失败格式则严格为 `data: null`（见「帧数据区返回格式」）。
> `cmd` 不在 `0` / `1` / `2` / `3` 时返回 `{"code":400,"message":"cmd 只支持 0x00 / 0x01 / 0x02 / 0x03","data":{"connected":false}}`，不向设备发帧。

## 二、帧命令字总表

| 命令字 | 名称 | 方向 | 请求数据区 | 应答数据区 |
| --- | --- | --- | --- | --- |
| `0x00` | CMD_HEARTBEAT | PC→设备 | `{}` | 统一信封，`data` 为 `{"version":"1.0"}` |
| `0x01` | CMD_TTS | PC→设备 | `{"text":"..."}` | 统一信封，`data` 为 `{"status":"done"}` 或 `code:400/500` |
| `0x02` | CMD_DEVICE_INFO | PC→设备 | `{}` | 统一信封，`data` 为设备详细信息（见「3.3」） |
| `0x03` | CMD_SERIAL_READ | PC→设备 | `{"serial":"/dev/ttyS3","baud":115200,"duration":2000}` | 统一信封，`data` 为 `{"hex":"..","bytes":N,"duration":Ms}`（见「3.4」） |
| `0x06` | CMD_ACK | 设备→PC | 无 | 无（通知类） |
| `0x80` | CMD_HEARTBEAT_RESPONSE | 设备→PC | 统一信封 | 无（通知类，不要求 ACK），`0x00 \| 0x80` |
| `0x81` | CMD_TTS_RESPONSE | 设备→PC | 统一信封 | 无（通知类，不要求 ACK），`0x01 \| 0x80` |
| `0x82` | CMD_DEVICE_INFO_RESPONSE | 设备→PC | 统一信封 | 无（通知类，不要求 ACK），`0x02 \| 0x80` |
| `0x83` | CMD_SERIAL_READ_RESPONSE | 设备→PC | 统一信封 | 无（通知类，不要求 ACK），`0x03 \| 0x80` |
| `0xFF` | CMD_ERROR | 设备→PC | 统一信封 `code:400`（未知命令） | 无（通知类） |

> 设备端不再有旧 `0x03`~`0x05`、`0x07` 业务命令字（现 `0x03` 已被串口读取重新占用），也没有关闭连接的命令字；
> 连接由 PC 侧主动关闭，设备端 `ServerSocket` 常驻监听。

`ProbeService.java:270-272` 计算 `unknown` 与 `respCmd = unknown ? CMD_ERROR : (cmd | 0x80)`。
后端 `DFM-service/routes/probe.py` 用 `r_cmd in (cmd | 0x80, CMD_ERROR)` 通用匹配响应帧，
因此 `0x00` 的响应帧 `0x80`、`0x01` 的响应帧 `0x81`、`0x02` 的响应帧 `0x82`、`0x03` 的响应帧 `0x83` **无需改后端**。

## 三、命令字与参数规范

### 3.1 心跳 `CMD_HEARTBEAT (0x00)`

**响应命令字**: `0x80`  
**描述**: 确认设备端探针服务在线，并返回当前程序版本。  
**实现位置**: `ProbeService.java:287-300`（`execute` 的 `CMD_HEARTBEAT` 分支）

#### 请求参数

数据区为 JSON 对象，**无必填字段**，传 `{}` 即可；多余字段被忽略。

```json
{}
```

**请求帧示例**（帧序 `0x09`，长度 2 字节 `02 00`，数据区 `{}`）:

```
AA 55 09 02 00 00 7B 7D 9B 93
```

> 上帧 CRC 为 `9B 93`，由 `DFM-service/routes/probe.py:96-102` 的 `pack_frame` 实算得出。

#### 返回参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 成功 `200`；取版本失败 `500` |
| `message` | string | 成功 `success`；失败 `version unavailable` 或 `version unavailable: <异常>` |
| `data` | object \| null | 成功为 `{"version": string}`；失败 `null` |
| `data.version` | string | 程序版本，取自 `AndroidManifest.xml` 的 `android:versionName`（当前 `1.0`），运行时由 `getPackageInfo().versionName` 读取 |

**成功响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {"version": "1.0"}
}
```

**失败响应**（版本信息不可用时）:

```json
{
  "code": 500,
  "message": "version unavailable",
  "data": null
}
```

**应答顺序**: `ACK (0x06)` → `CMD_HEARTBEAT_RESPONSE (0x80)`，两帧同帧序。

#### 调用方式

```http
POST http://localhost:3000/api/probe/check
Content-Type: application/json

{"deviceId": "202600298120"}
```

也可经 `/api/probe/message` 显式指定命令字：

```http
POST http://localhost:3000/api/probe/message
Content-Type: application/json

{"deviceId": "202600298120", "cmd": 0, "data": {}}
```

### 3.2 TTS 语音朗读 `CMD_TTS (0x01)`

**响应命令字**: `0x81`  
**描述**: 调用设备系统 TTS 引擎朗读文本，朗读完成后返回。  
**实现位置**: `ProbeService.java:301-315`（参数校验）、`ProbeService.java:559-600`（`speak`）

#### 请求参数

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `text` | string | 必填，且 `trim()` 后非空 | 要朗读的文本；缺失或非字符串返回 `400 text must be a string`，空白文本返回 `400 empty text` |

```json
{"text": "设备语音测试"}
```

**请求帧示例**（帧序 `0x0A`，长度 `12 00` = 18 字节）:

```
AA 55 0A 12 00 01 7B 22 74 65 78 74 22 3A 20 22 E4 BD A0 E5 A5 BD 22 7D 9C A8
```

> 上帧数据区为 `{"text": "你好"}`（UTF-8），CRC `9C A8` 由 `pack_frame` 实算得出。

#### 返回参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 成功 `200`；参数错误 `400`；引擎/朗读失败 `500` |
| `message` | string | 成功 `success`；失败为具体原因 |
| `data` | object \| null | 成功为 `{"status": string}`；失败 `null` |
| `data.status` | string | 朗读成功固定 `done` |

> TTS 语音播放为 `0x01` 命令字，页面「TTS 语音朗读」卡片调用；本次未改动该实现。

**成功响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {"status": "done"}
}
```

**失败响应**（示例：缺少 `text`）:

```json
{
  "code": 400,
  "message": "text must be a string",
  "data": null
}
```

#### TTS 错误码

| `code` | `message` | 触发条件 |
| --- | --- | --- |
| `400` | `text must be a string` | `text` 缺失或不是字符串 |
| `400` | `empty text` | `text` 为空白字符串 |
| `500` | `tts engine unavailable` | 系统 TTS 引擎初始化失败 / 超时（最多等 30 秒） |
| `500` | `tts speak rejected: <code>` | `TextToSpeech.speak()` 返回非 `SUCCESS` |
| `500` | `tts timeout` | 朗读 60 秒未完成 |
| `500` | `tts engine reported error` | 引擎回调报告朗读失败 |
| `500` | `execute failed: <异常>` | `speak()` 抛出未预期异常 |

> TTS 失败**不会断开连接**，服务继续常驻；下次请求可重试。

**应答顺序**: `ACK (0x06)` → `CMD_TTS_RESPONSE (0x81)`，两帧同帧序。
后端 `RESPONSE_TIMEOUT = 120s`，覆盖引擎初始化 30s + 朗读 60s。

#### 调用方式

```http
POST http://localhost:3000/api/probe/message
Content-Type: application/json

{"deviceId": "202600298120", "cmd": 1, "data": {"text": "设备语音测试"}}
```

### 3.3 设备详细信息 `CMD_DEVICE_INFO (0x02)`

**响应命令字**: `0x82`  
**描述**: 设备端 APK 采集本机基础信息、串口节点、摄像头与外设/输入设备，一次回帧返回。  
**实现位置**: `ProbeService.java:316-323`（`execute` 分支）、`ProbeService.java:345-503`（`deviceInfo` 及采集方法）

#### 请求参数

数据区为 JSON 对象，**无必填字段**，传 `{}` 即可；多余字段被忽略。

```json
{}
```

**请求帧示例**（帧序 `0x0B`，长度 `02 00`，数据区 `{}`）:

```
AA 55 0B 02 00 02 7B 7D 3B B1
```

#### 返回参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 成功 `200`；采集整体失败 `500 device info failed: <异常>` |
| `message` | string | 成功 `success`；失败为具体原因 |
| `data` | object \| null | 成功为设备详细信息对象；失败 `null` |
| `data.androidVersion` | string | 安卓版本（`Build.VERSION.RELEASE`，如 `11`） |
| `data.sdk` | int | SDK 版本号（`Build.VERSION.SDK_INT`） |
| `data.model` | string | 机型（`Build.MODEL`） |
| `data.manufacturer` | string | 厂商（`Build.MANUFACTURER`） |
| `data.device` | string | 设备代号（`Build.DEVICE`） |
| `data.displayVersion` | string | 构建显示版本（`Build.DISPLAY`） |
| `data.sn` | string | 序列号（`getprop ro.serialno`），不可读时为 `Unknown` |
| `data.buildDate` | string | 构建日期（`getprop ro.build.date`），不可读时为 `Unknown` |
| `data.kernelVersion` | string | `/proc/version` 首行，不可读时为 `Unknown` |
| `data.serialPorts` | array\<string\> | `/dev` 下 `ttyS*` / `ttyUSB*` / `ttyACM*` 串口节点路径，排序后返回；不可读时为空数组 |
| `data.cameras` | array\<object\> | `CameraManager` 枚举的摄像头，见下表；不可用时为空数组 |
| `data.peripherals` | array\<object\> | `InputManager` 输入设备 + `UsbManager` USB 设备，见下表；不可用时为空数组 |

**`data.cameras[]` 元素**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 摄像头 id（如 `0`、`1`） |
| `facing` | string | `front` / `back` / `external` / `unknown`（取 `LENS_FACING` 失败时降级 `unknown`） |
| `resolution` | string | `WxH`（`SENSOR_INFO_PIXEL_ARRAY_SIZE`）或 `unknown` |

**`data.peripherals[]` 元素**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | `input`（输入设备）或 `usb`（USB 设备） |
| `id` | int | 设备 id |
| `name` | string | 设备名称，取不到时 `unknown` / `getDeviceName()` |
| `vendorId` | int | 仅 `type:usb`：厂商 id |
| `productId` | int | 仅 `type:usb`：产品 id |

**成功响应**（结构示意，列表内容随真机变化）:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "androidVersion": "11",
    "sdk": 30,
    "model": "rk3568_r",
    "manufacturer": "rockchip",
    "device": "rk3568_r",
    "displayVersion": "rk3568_r-userdebug 11 ...",
    "sn": "202600298120",
    "buildDate": "Tue Sep 29 11:12:30 CST 2026",
    "kernelVersion": "Linux version 4.19.232 ...",
    "serialPorts": ["/dev/ttyS0", "/dev/ttyS1"],
    "cameras": [{"id": "0", "facing": "back", "resolution": "1920x1080"}],
    "peripherals": [{"type": "input", "id": 1, "name": "touchscreen"}]
  }
}
```

**失败响应**（采集整体抛异常时）:

```json
{
  "code": 500,
  "message": "device info failed: <异常>",
  "data": null
}
```

> 单项采集失败**不会**使整帧失败：`getprop` / `kernelVersion` 各自降级 `Unknown`，
> 串口 / 摄像头 / 外设列表各自 `catch` 后降级为空数组或含 `unknown` 字段的项，
> 互不影响。列表长度取决于真机系统是否允许读取对应节点/服务。

**应答顺序**: `ACK (0x06)` → `CMD_DEVICE_INFO_RESPONSE (0x82)`，两帧同帧序。

#### 调用方式

```http
POST http://localhost:3000/api/probe/message
Content-Type: application/json

{"deviceId": "202600298120", "cmd": 2, "data": {}}
```

### 3.4 串口读取 `CMD_SERIAL_READ (0x03)`

打开设备端指定串口节点，配置波特率后按**时长**或**字节数上限**读取原始数据，返回 hex 字符串。
设备端 APK 直接 `open` 串口节点读取，**不经 adb shell**，要求设备已 root 且串口节点可读写。

- **实现位置**: `ProbeService.java` 的 `serialRead()`、`isValidBaud()`
- **请求参数**（`data` 对象）:

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `serial` | string | 是 | 串口设备节点，如 `/dev/ttyS3`；空或不存在的节点回 `400` |
| `baud` | int | 是 | 波特率，仅支持 `1200` `2400` `4800` `9600` `19200` `38400` `57600` `115200` `230400` `460800` `921600` `1500000` `3000000`；其余回 `400` |
| `duration` | int | 与 `maxBytes` 至少一个 | 读取时长（毫秒），最大 `10000`；到时即停 |
| `maxBytes` | int | 与 `duration` 至少一个 | 读取字节上限，最大 `4096`；读满即停 |

> `duration` 与 `maxBytes` 都给时**先到者停**；都缺时回 `400 duration or maxBytes is required`。

**返回参数**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | `200` 成功 / `400` 参数错误 / `500` 设备端失败 |
| `message` | string | `success` 或错误信息 |
| `data` | object \| null | 成功为 `{hex, bytes, duration}`；失败 `null` |
| `data.hex` | string | 读取到的字节，空格分隔的大写 hex（如 `"01 02 03"`）；无数据为空串 `""` |
| `data.bytes` | int | 实际读取字节数 |
| `data.duration` | int | 实际耗时（毫秒） |

**成功示例**:

```json
{
  "code": 200,
  "message": "success",
  "data": {"hex": "01 03 00 00 00 02", "bytes": 6, "duration": 1987}
}
```

**失败示例**（串口打不开 / `stty` 失败，多为权限不足）:

```json
{"code": 500, "message": "serial read failed: stty failed (exit 1): ...", "data": null}
```

**设备端实现要点**: 先 `stty -F <serial> <baud> raw -echo` 配置波特率与原始模式（需 root），
再用 `RandomAccessFile` 以只读打开节点循环读取，每轮最多 512 字节、无数据时 `sleep 10ms` 轮询，
按 `duration` / `maxBytes` 停止。参数错误（`IllegalArgumentException`）回 `400`，其余异常回 `500`。

**应答顺序**: `ACK (0x06)` → `CMD_SERIAL_READ_RESPONSE (0x83)`，两帧同帧序。

#### 调用方式

```http
POST http://localhost:3000/api/probe/message
Content-Type: application/json

{"deviceId": "202600298120", "cmd": 3, "data": {"serial": "/dev/ttyS1", "baud": 9600, "duration": 2000, "maxBytes": 1024}}
```

**真机实测返回**（设备 `202600298120`，已 root，`/dev/ttyS1` -> `/dev/ttyDC1`，刷卡模块 UART 接 `/dev/ttyS1`、`9600`）：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "hex": "02 09 01 50 7A EE 66 AA 03 02 09 01 50 7A EE 66 AA 03",
    "bytes": 18,
    "duration": 4563
  }
}
```

> 页面「串口读取」卡片提供串口路径、波特率、时长、字节数输入，设备未 root 或节点不可读写时
> 通常回 `500 serial read failed`。

#### 读取结果的帧格式（业务层，非帧协议）

`data.hex` 是串口原始字节，帧协议层不做解析。所接刷卡模块（依据用户提供的
《电子班牌刷卡二次开发接口.doc》）在 `9600` 下输出固定 9 字节帧：

| 字节 | 值 | 说明 |
| --- | --- | --- |
| 1 | `0x02` | 数据头（固定） |
| 2 | `0x09` | 整帧长度 9 字节（含头尾） |
| 3 | `0x01` / `0x02` | 卡片类型：`0x01` MIFARE 1K、`0x02` EM4100 |
| 4~7 | SN0~SN3 | 4 字节卡号 |
| 8 | BCC | 第 2~7 字节逐字节异或 |
| 9 | `0x03` | 数据结尾（固定） |

- 模块文档示例 `02 09 02 04 2E 53 82 F0 03`：卡类型 `0x02` EM4100、卡号 `04 2E 53 82`、
  BCC = `09 ^ 02 ^ 04 ^ 2E ^ 53 ^ 82 = F0`。
- 真机实测 `02 09 01 50 7A EE 66 AA 03`：卡类型 `0x01` MIFARE 1K、卡号 `50 7A EE 66`、
  BCC = `09 ^ 01 ^ 50 ^ 7A ^ EE ^ 66 = AA`，校验通过。
- 一次刷卡可能输出多帧相同数据（实测 `bytes: 18` = 2 帧），需按 `0x02`...`0x03` 切帧去重。
- 实测出现过短帧 `02 09 01 61 12 C6 AE 03`（`bytes: 8`，缺 BCC `13`），
  属读取窗口内未收满整帧；解析前须按帧头 / 长度 / 帧尾 + BCC 校验，不完整帧丢弃或重读。
- `data.duration` 为设备端实际耗时，实测 `6862` / `4563` 均大于请求 `duration: 2000`
  （原因待查）；是否读到数据以 `bytes` / `hex` 为准，不要用 `duration` 判断。

### 3.5 错误码总表

| `code` | 含义 | `data` | 典型 `message` |
| --- | --- | --- | --- |
| `200` | 成功 | 业务数据对象 | `success` |
| `400` | 请求参数错误 | `null` | `text must be a string`、`empty text`、`serial is required`、`baud must be one of: ...`、`duration or maxBytes is required`、`unknown cmd: 0x7e` |
| `500` | 设备端内部错误 | `null` | `version unavailable`、`tts timeout`、`device info failed: <异常>`、`serial read failed: <异常>`、`response too large: N` |

## 四、边界与注意

- **数据区上限**: 长度字段为 2 字节（低字节在前），单帧最多 65535 字节。
  响应超过 65535 字节时，`ProbeService.java:273-276` 把整帧改写为统一格式的
  `{"code":500,"message":"response too large: N","data":null}`，不截断、不丢帧。
  请求数据区超过 65535 字节时，PC 侧 `DFM-service/routes/probe.py:240` 与
  `DFM-probe/pc/probe_test.py` 的 `pack_frame` 直接拒绝组帧。
- **非对象数据区**: 数据区不是 JSON 对象（如 `[]`）时，`ProbeService.java:253-259` 丢弃该帧
  且不回 ACK，调用方等待 ACK 超时。
- **重复帧序**: 同一帧序重传只回 ACK、不重复执行业务（`ProbeService.java:260-265`），
  避免 TTS 被念两遍。
- **未知命令**: `0x7E` 等未登记命令走 `0xFF CMD_ERROR`，应答数据区为统一格式的
  `{"code":400,"message":"unknown cmd: 0x7e","data":null}`（`ProbeService.java:269`、`:283-286`）。
- **无关闭连接命令字**: 旧 `CMD_QUIT (0x05)` 已删除，连接由 PC 侧主动关闭，设备端服务常驻。
- **TTS 依赖**: 朗读成功需设备已安装可用的系统 TTS 引擎；无真机时此项未做端到端验证。
- **设备详细信息依赖**: `0x02` 的串口 / 摄像头 / 外设列表与 `sn` 依赖真机系统是否允许读取
  `/dev`、`CameraManager`、`InputManager` / `UsbManager`；不可读时降级为空数组或 `Unknown`，
  无真机时列表内容未做端到端验证，且可能与 PC 侧 `adb shell` 采集口径不同。
- **串口读取依赖**: `0x03` 要求设备已 root 且串口节点（如 `/dev/ttyS1`）可读写；
  `stty` 配置失败或 `open` 被拒通常回 `500 serial read failed`。读取结果依赖是否有数据到达，
  空闲串口在 `duration` 内可能读到 `bytes: 0`、`hex: ""`（属正常）。
  已在真机 `202600298120`（`/dev/ttyS1`、`9600`）端到端读到刷卡数据，帧格式与实测现象见 `3.4`；
  模块若走 WG 输出模式（CST 引脚选择 W26/W34）则 UART TXD 无数据，读串口恒为空。
- **版本来源**: `data.version` 来自 `DFM-probe/AndroidManifest.xml` 的
  `android:versionName`（当前 `1.0`），升级版本时改此处即可，代码无需改动。
- **部署要求**: 本版命令字为破坏性变更，新 `DFMProbe.apk` 必须与新
  `DFM-service/routes/probe.py`、`DFM-probe/pc/probe_test.py`、`DFM-frontend` 一起使用，
  旧版三端不兼容。
