# 探针接口文档 v1.0

## 基础信息

- **HTTP 服务地址**: `http://localhost:3000`（后端 `DFM-service`，路由 `DFM-service/routes/probe.py`）
- **设备端监听**: TCP `21104`（`DFM-probe/DFMProbe.apk`，`ProbeService`）
- **启动方式**: 后端每次请求发幂等广播 `com.dfm.probe.START`；服务常驻监听 21104，不 force-stop
- **帧协议**: 见根目录 `probe与service通讯协议.md`
- **设备端源码**: `DFM-probe/java/com/dfm/probe/ProbeService.java`（下文简称 `ProbeService.java`）
- **适用构建**: 含 `CMD_DEVICE_INFO (0x07)` 与 2 字节长度帧协议的 `DFMProbe.apk`

---

## 统一规范

### 请求方式

HTTP 接口统一使用 **POST**，参数放入请求体（JSON 格式）。

### HTTP 返回格式

与 `DFM-service/API文档_v2.md`「统一规范」保持一致：

**成功响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**失败响应**:

```json
{
  "code": 400,
  "message": "错误信息",
  "data": null
}
```

**状态码说明**:

- `200`: 请求已受理；探针是否通讯成功看 `data.connected`，成功时 `message` 为 `通讯正常`
- `400`: 请求参数错误（如 `deviceId` 为空）
- `500`: 服务端内部错误（`/api/probe/*` 目前不使用该码；设备端 `CMD_DEVICE_INFO` 的失败响应用 `code: 500`，见「三」）

> 注意：`/api/probe/*` 三个端点在通讯失败时仍返回 `code: 200`，`message` 为失败原因（如
> `ACK 等待超时（共发 4 次）`），`data.connected` 为 `false`。仅参数校验失败返回 `code: 400`。

### 帧返回格式

设备端帧数据区为 UTF-8 JSON 对象。业务帧（0x01~0x05、0x07）先回 ACK（`0x06`），
再回同帧序响应帧，响应帧命令字 = `请求命令字 | 0x80`，不要求 ACK。
CRC 错或长度非法的帧直接丢弃且不回 ACK；同一帧序重复帧只回 ACK、不重复执行业务。
长度字段为 2 字节、低字节在前，单帧数据区 **最多 65535 字节**。

## 一、HTTP 接口

三个端点统一返回 `{"code":200,"message":"...","data":{...}}`。

| 接口 | 请求体 | 描述 |
| --- | --- | --- |
| `POST /api/probe/check` | `{"deviceId":"..."}` | 只发一帧 CMD_PING 探测，不安装 APK |
| `POST /api/probe/connect` | `{"deviceId":"..."}` | 先 `adb install -r DFMProbe.apk`，再发一帧 CMD_PING |
| `POST /api/probe/message` | `{"deviceId":"...","cmd":1,"data":{}}` | 按命令字发一帧，`data` 作数据区，返回设备应答 |

### 1. 检测探针通讯

**接口**: `POST /api/probe/check`  
**描述**: 不安装 APK，只发一帧 `CMD_PING (0x01)` 确认设备端服务是否在监听。  
**请求体**:

```json
{"deviceId": "202600298120"}
```

**响应**（结构示意，hex 与端口为示例值）:

```json
{
  "code": 200,
  "message": "通讯正常",
  "data": {
    "connected": true,
    "deviceId": "202600298120",
    "seq": 1,
    "cmd": 1,
    "request": {"payload": "probe-1762400000"},
    "response": {"ok": true, "payload": "probe-1762400000"},
    "frame": "AA 55 01 ...",
    "frames": {"tx": "AA 55 01 ...", "ack": "AA 55 01 00 00 06 ...", "rx": "AA 55 01 ... 81 ..."},
    "host": "127.0.0.1",
    "port": 41234
  }
}
```

> `request` 由 `DFM-service/routes/probe.py:240` 生成：`data is None` 时填
> `{"payload":"probe-<时间戳>"}`。USB 设备的 `port` 是系统分配的随机 `adb forward`
> 本地端口；网络设备（`deviceId` 含 `:`）的 `port` 固定为 `21104`。

### 2. 安装并连接探针

**接口**: `POST /api/probe/connect`  
**描述**: 覆盖安装 APK 后发一帧 `CMD_PING (0x01)`，供页面「安装通讯」使用。  
**请求体**:

```json
{"deviceId": "202600298120"}
```

**响应**: 同「1. 检测探针通讯」，`data` 字段一致。

> `DFMProbe.apk` 路径由 `DFM-service/routes/probe.py:39` 的 `APK_PATH` 解析：
> `DFM-probe/DFMProbe.apk`。源码运行可解析；PyInstaller 打包成 exe 后该路径失效，
> 此端点会返回「找不到 APK」，`/api/probe/check` 与 `/api/probe/message` 不受影响。

### 3. 发送任意命令帧

**接口**: `POST /api/probe/message`  
**描述**: 按指定命令字向设备发一帧，返回设备应答，供页面调试与本文档新增接口调用。  
**请求体**:

```json
{"deviceId": "202600298120", "cmd": 7, "data": {}}
```

**字段说明**:

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `deviceId` | string | 必填，非空 | ADB 设备序列号；含 `:` 视为网络设备，直连 `<IP>:21104` |
| `cmd` | int | 必填，0~255 | 帧命令字，见「二、帧命令字总表」 |
| `data` | object | 可选，默认 `{}` | 帧数据区，必须是 JSON 对象；序列化后不得超过 65535 字节 |

**响应**: 同「1. 检测探针通讯」；`data.response` 为设备端应答 JSON，
`data.frame` 为发送帧 hex，`data.frames` 为 `tx` / `ack` / `rx` 三段真实帧 hex。

**失败响应**:

```json
{
  "code": 400,
  "message": "deviceId 不能为空",
  "data": {"connected": false}
}
```

## 二、帧命令字总表

| 命令字 | 名称 | 方向 | 数据区 | 应答数据区 |
| --- | --- | --- | --- | --- |
| `0x01` | CMD_PING | PC→设备 | `{"payload":"..."}` | `{"ok":true,"payload":"..."}` |
| `0x02` | CMD_ECHO | PC→设备 | `{"payload":"..."}` | `{"ok":true,"payload":"..."}` |
| `0x03` | CMD_TTS | PC→设备 | `{"text":"..."}` | `{"ok":true,"status":"done"}` / `{"ok":false,"message":"..."}` |
| `0x04` | CMD_INFO | PC→设备 | `{}` | `{"ok":true,"device":...,"sdk":...,"abi":...,"package":...}` |
| `0x05` | CMD_QUIT | PC→设备 | `{}` | `{"ok":true,"message":"bye"}`，只关当前连接，服务继续监听 |
| `0x06` | CMD_ACK | 设备→PC | 无 | 无（通知类） |
| `0x07` | **CMD_DEVICE_INFO** | PC→设备 | `{}` | **见「三、获取设备信息」**（14 项字段） |
| `0x81`–`0x85`、`0x87` | CMD_RESPONSE | 设备→PC | UTF-8 JSON | 无（通知类，不要求 ACK），命令字 = `请求命令字 \| 0x80` |
| `0xFF` | CMD_ERROR | 设备→PC | `{"ok":false,"message":"unknown cmd: 0x.."}` | 无（通知类） |

响应帧命令字由 `ProbeService.java:270` 计算：`respCmd = unknown ? CMD_ERROR : (cmd | 0x80)`。
后端 `DFM-service/routes/probe.py:204` 用 `r_cmd in (cmd | 0x80, CMD_ERROR)` 通用匹配响应帧，
因此新增命令 `0x07` 的响应帧 `0x87` **无需改后端**。

## 三、获取设备信息

**命令字**: `0x07 CMD_DEVICE_INFO`  
**响应命令字**: `0x87`  
**描述**: 返回设备端 APK 采集到的 14 项设备信息，字段集与 service `/api/device/info` 一致。  
**实现位置**: `ProbeService.java:304-324`（`execute` 的 `CMD_DEVICE_INFO` 分支）、
`ProbeService.java:347-453`（采集辅助方法）

### 返回格式

与 `DFM-service/API文档_v2.md` 的 HTTP 统一规范对齐外层信封：

**成功响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "status": "在线",
    "model": "rk3568_r",
    "version": "11",
    "manufacturer": "rockchip",
    "deviceName": "rk3568_r",
    "displayVersion": "rk3568_r-userdebug 11 RD2A.211001.002 eng.lwl.20260929.111101-ne98dad0d06423 release-keys",
    "androidVersion": "11",
    "kernelVersion": "4.19.232 #3634 SMP PREEMPT Tue Sep 29 11:12:09 CST 2026",
    "buildDate": "Tue Sep 29 11:12:30 CST 2026",
    "codename": "rk3568_r",
    "unlockStatus": "已解锁（警告）",
    "sn": "202600298120",
    "wifiMac": "84:88:32:2b:c2:88",
    "ethMac": "c6:0f:b3:68:35:62"
  }
}
```

**失败响应**（`execute` 抛异常时，`ProbeService.java:329-343`）:

```json
{
  "code": 500,
  "message": "execute failed: java.lang.Exception",
  "data": null
}
```

**data 字段说明**（14 项，字段名与 `DFM-service/routes/adb_utils.py:368-383` 一致）:

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 固定 `在线` | PC 侧 `adb devices` 的连接状态设备端无法判定；能应答 `0x87` 即说明探针服务在线 |
| `model` | string | `getprop ro.product.model`，缺失回退 `Build.MODEL` | 设备型号 |
| `version` | string | `getprop ro.build.version.release`，缺失回退 `Build.VERSION.RELEASE` | Android 版本 |
| `manufacturer` | string | `getprop ro.product.manufacturer`，缺失回退 `Build.MANUFACTURER` | 厂商 |
| `deviceName` | string | `getprop ro.product.name`，缺失回退 `Build.PRODUCT` | 产品名 |
| `displayVersion` | string | `getprop ro.build.display.id`，缺失回退 `Build.DISPLAY` | 完整构建版本 |
| `androidVersion` | string | 同 `version` | Android 版本 |
| `kernelVersion` | string | `/proc/version` 首行正则提取，否则首行前 100 字符 | 内核版本，读不到为 `Unknown` |
| `buildDate` | string | `getprop ro.build.date` | 构建时间 |
| `codename` | string | `getprop ro.product.device`，缺失回退 `Build.DEVICE` | 设备代号 |
| `unlockStatus` | string | `getprop ro.boot.verifiedbootstate` 映射 | green=已解锁 / orange=已解锁（警告） / yellow=未锁定 / red=已锁定 / unknown=未知，其余原样 |
| `sn` | string | `getprop ro.serialno` | 序列号，缺失为 `Unknown` |
| `wifiMac` | string | `getprop ro.boot.wifimacaddr`，无效则 `/sys/class/net/wlan0/address` | 无效或全失败为 `Unknown` |
| `ethMac` | string | `getprop ro.boot.ethmacaddr`，无效则 `/sys/class/net/eth0/address` | 无效或全失败为 `Unknown` |

> **与 `/api/device/info` 的区别**：字段集与取值口径对齐 `adb_utils.py`，但数据由设备端
> APK 直接执行 `getprop` / 读 `/proc/version` 与 sysfs 得到，不经 PC 侧 `adb shell`。
> `status` 固定 `在线`；`sn` / `wifiMac` / `ethMac` 在设备端属性或 sysfs 不可读时会回退
> `Unknown`，可能与 PC 侧 `adb` 取到的值不同。无真机时这些值未做端到端验证。

### 请求

数据区为 UTF-8 JSON 对象，无必填字段，传 `{}` 即可：

```json
{}
```

**请求帧示例**（帧序 `0x09`，数据区 `{}`，长度 2 字节 `02 00`）:

```
AA 55 09 02 00 07 7B 7D <crc_lo> <crc_hi>
```

**应答顺序**: `ACK (0x06)` → `CMD_RESPONSE (0x87)`，两帧同帧序。

```http

```

### 边界与注意

- **数据区上限**：长度字段已扩为 2 字节（低字节在前），单帧最多 65535 字节；14 项字段的
  完整响应紧凑序列化约 531 字节，可单帧容纳。超过 65535 字节时
  `ProbeService.java:272-277` 会把整帧响应改写为
  `{"ok":false,"message":"response too large: N"}`。该兜底是**帧协议级**格式，
  不带 `code/message/data` 信封，调用方需兼容。
- **`ok` 字段例外**：根目录 `probe与service通讯协议.md`「数据区编码」约定「业务结果 JSON
  统一带 `ok` 布尔字段」。本接口为对齐 service 返回格式，成功/失败响应均**不带 `ok`**；
  其余命令字仍保持原 `ok` 格式，未改动。
- **非对象数据区**：数据区不是 JSON 对象（如 `[]`）时，`ProbeService.java:252-256` 丢弃该帧
  且不回 ACK，调用方等待 ACK 超时。
- **重复帧序**：同一帧序重传只回 ACK、不重复执行业务（`ProbeService.java:258-262`）。
- **未知命令**：`0x7E` 等未登记命令仍走 `0xFF CMD_ERROR`（`ProbeService.java:267-268`）。
- **CMD_INFO (0x04) 保持不变**：仍返回 `{"ok":true,"device":...,"sdk":...,"abi":...,"package":...}`，
  需要 `ok` 格式的调用方继续使用 `0x04`。
- **部署要求**：2 字节长度帧协议为破坏性变更，新 `DFMProbe.apk` 必须与新
  `DFM-service/routes/probe.py`、`DFM-probe/pc/probe_test.py` 一起使用，旧版三端不兼容。
